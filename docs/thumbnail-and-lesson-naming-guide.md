# Thumbnail and Lesson Naming Guide

Use this guide to keep your lesson exports, thumbnails, module titles, and upload names visually consistent.

---

## 1. Master naming rules

### Course title

`n8n M-Pesa Mastery`

### Subtitle

`Build Production-Ready STK Push Payment Workflows - No Backend code`

### Tier names

`Starter · Pro · Agency`

These should be written exactly the same way everywhere.

---

## 2. Thumbnail rules

### Keep thumbnails short

Do **not** put the full subtitle on every thumbnail.

Use:

- the course title as the persistent brand line
- one short promise or module topic
- large readable text

### Good thumbnail structure

Top line:

`n8n M-Pesa Mastery`

Main line examples:

- `STK Push in n8n`
- `Handle M-Pesa Callbacks`
- `Reconcile Failed Payments`
- `Deploy to Production`
- `WooCommerce + M-Pesa`

### Avoid on thumbnails

- long paragraphs
- full lesson titles
- tiny code screenshots as the hero visual
- too many colors
- more than 6–8 words of large text

## 4. Lesson title rules

### Student-facing lesson titles

Keep titles:

- outcome-oriented
- short
- literal
- consistent in casing

### Good examples

- `What is n8n?`
- `Installing n8n Locally`
- `Understanding the Daraja API`
- `Building the STK Push Workflow`
- `Handling the Callback`
- `Running Reconciliation`

### Avoid

- clever vague names
- titles that depend on jargon without context
- two different names for the same concept

## 6. Upload title convention

### Recommended format

```text
Module 4 : Building the STK Push Workflow
Lesson 4.1 : Designing the STK Push API
```

or if your platform supports nesting cleanly:

```text
4.1 Designing the STK Push API
```

Keep the numbering consistent with the scripts in `docs/scripts/`.
